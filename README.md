# Agent Hub

Agent Hub 是一个面向多人、多 Agent 开发的项目协作房间。它让每位成员的 Agent 读取同一份实时项目状态，并在写文件前自动登记工作范围、检查冲突、同步实际改动。

它共享的是路径、工作范围、项目结构、依赖关系、决定、验证和风险等结构化信息，不会合并模型内部记忆，也不会同步成员的私人聊天或隐藏思考。

> 当前版本是 Windows x64 局域网验证版。房主电脑运行房间服务，其他成员通过邀请地址和房间码加入。

## 普通用户安装

1. 在 GitHub 项目的 **Releases** 页面下载 `AgentHub-Setup-版本号-x64.exe`。
2. 运行安装程序并启动 Agent Hub。
3. 当前安装包尚未进行商业代码签名，Windows SmartScreen 可能显示“Windows 已保护你的电脑”。请先核对下载来源和 Release 中的 `SHA256SUMS.txt`；确认来自可信仓库后，再选择“更多信息”继续运行。
4. 团队中的每位成员都安装一次。房主和成员使用同一个安装包。

推荐使用 Setup 安装版。`AgentHub-Portable-版本号-x64.exe` 可以临时创建或加入房间，但便携版的运行路径不稳定，因此不会安装 Codex 自动接入。要获得日常自动保护，请使用安装版。

## 第一次使用

### 房主创建房间

1. 打开 Agent Hub，选择“创建房间”。
2. 选择本机的 Git 项目目录，填写房间名称、项目名称和默认分支。
3. 点击“创建并进入”。
4. 打开“连接设置”，把“房主邀请地址”和“房间码”发给协作成员。
5. 保持 Agent Hub 在房主电脑上运行。关闭窗口后程序会留在系统托盘；房主彻底退出或关机时，房间会暂时离线。

如果 Windows 防火墙询问是否允许网络访问，只应在可信的专用网络中允许。邀请地址通常类似 `http://192.168.1.10:4173`，实际端口以界面显示为准。

### 成员加入房间

1. 成员打开 Agent Hub，选择“加入房间”。
2. 选择自己电脑上对应的同一个 Git 项目目录。
3. 粘贴房主发送的邀请地址和房间码，填写显示名称。
4. 点击“加入房间”。加入后会立即看到当前成员、正在进行的工作、决定、验证、风险和最近的项目扫描，而不是只能看到加入之后的新消息。

成员必须能通过局域网访问房主电脑。如果连接失败，请检查两台电脑是否在同一可信网络、房主程序是否仍在运行，以及防火墙是否允许 Agent Hub。

### 每位成员连接 Codex

1. 加入房间后打开“连接设置”。
2. 点击“安装连接”。Agent Hub 会为当前 Windows 用户写入 MCP 与四类协作 Hook 配置，并为已有 Codex 配置创建备份。
3. 重启 Codex。
4. Codex 第一次加载这些非托管 Hook 时会要求信任确认。核对命令来自已安装的 Agent Hub 后再确认；这是 Codex 的安全保护，Agent Hub 不会绕过它。

成员凭证由 Windows DPAPI 加密后保存在本机，不会写入项目仓库。不同成员应各自加入房间并安装连接，不要相互复制成员凭证。

### 房间管理与服务更新

房主或管理员进入“房间管理”后，可以调整自动范围锁定、管理成员并导出/导入结构化项目上下文。房主额外拥有房主交接、解散房间和更新检查权限；管理员不能解散房间或转移房主。

如果房主服务配置了内网更新清单，房主可在管理界面检查并准备更新包。配置方式：

```powershell
$env:AGENT_HUB_UPDATE_MANIFEST_URL="http://内网地址/agent-hub/manifest.json"
```

更新清单必须包含 `version`、`protocolVersion`、`schemaVersion`、`packageUrl` 和 64 位十六进制 `sha256`，可选 `sizeBytes` 与 `notes`。更新包应是可独立运行的 Node `.mjs` 房间服务入口，并从 `HOST`、`PORT`、`AGENT_HUB_DATA_DIR` 读取运行参数。Agent Hub 会先下载、校验并暂存更新包，同时备份 SQLite 数据库；房主点击“应用更新”后 supervisor 会短暂重启服务，健康检查失败则自动恢复旧入口。

## 日常怎么用

完成首次设置后，正常情况下只需要保持 Agent Hub 运行，然后照常在 Codex 中打开该项目并开发：

- 会话开始时，Codex 会收到房间的当前快照。
- 写文件前，本地组件会识别目标路径并自动领取尽可能小的限时工作范围。
- 长时间工作时会自动续期；会话结束时会同步实际改动并释放范围。
- 同一成员同时打开多个 Agent 时，每个会话只使用自己的工作范围；关闭一个会话不会释放另一个会话的租约。
- 如果目标与他人的高风险范围冲突，写入会被暂停；普通源码重叠会要求明确协调。
- 如果写入后的真实 Git 变化超出已领取范围，系统会登记风险并要求 Agent 停止继续修改。
- 会话开始前已经 dirty 的文件会保存本地指纹；之后同一路径再次变化，仍会被识别为本次会话的修改。
- 检测到越界写入后，当前会话会进入持续隔离，后续写操作保持拒绝，直到成员检查差异并结束该会话。
- 后台扫描会定期同步项目结构、规则文件摘要、依赖关系和受影响系统等元数据。

因此，用户不需要手工维护日常租约或重复填写协作记录。只有发生冲突、失败验证、未解决风险、房主离线或无法判断写入路径时，才需要人工处理。

## 它能保证什么

Agent Hub 能显著降低两个人在不同 Agent 上修改耦合系统时相互破坏的概率，但不能绝对保证语义兼容。路径不重叠也可能通过接口、数据、时序或运行时行为产生影响。

系统会组合使用范围冲突、C# 结构分析、Unity GUID 与 asmdef 关系、Git 共改历史、规则摘要、验证记录和共享分支门禁来提前暴露风险。最终仍必须依赖项目测试、代码审查和 Unity 等真实运行环境验证。

更完整的产品原理、能力边界与 Git 行为见 [rule.md](rule.md)。

## Git 会不会改变

Agent Hub 不安装本地 Git commit/push Hook，也不会替代分支、合并和代码审查。你仍然使用原来的 `git commit` 和 `git push` 流程。

仓库内提供了可选的 CI 共享分支门禁。团队配置 Agent Hub 地址和成员凭证后，门禁会在共享分支的 CI 或 Release 阶段检查阻塞冲突、未解决的 critical 风险和最新失败验证。它影响的是 CI/发布结果，不会悄悄改写本地提交。未配置门禁变量时，现有工作流会明确跳过该检查。

## 网络与安全边界

- 当前桌面版使用 HTTP 局域网房间，只适合可信内网验证。
- 不要把局域网 HTTP 地址直接暴露到公网，也不要通过不可信网络传输房间凭证。
- 跨地域或正式团队部署应使用持续在线的内网主机与 HTTPS，并配套访问控制、备份和服务监控；当前桌面版不提供一键公网部署。
- 房间默认同步结构化元数据，不上传源码全文、补丁、环境变量、密钥、私人提示词或模型隐藏思考。成员手工填写记录时仍应避免粘贴敏感内容。
- Git、项目源码、人工批准的项目规则和权威配置仍是最终事实来源。
- 当前 A 版用于可信团队内的防误操作；会话 ID 不是独立登录凭证，不要把同一成员凭证复制给其他人或不受信设备。

## 开发与构建

需要 Node.js 22.13 或更高版本，以及 pnpm 11。

```powershell
pnpm install
pnpm dev
```

浏览器开发服务默认监听 `http://localhost:4173`。常用检查和 Windows 打包命令：

```powershell
pnpm typecheck
pnpm test
pnpm build
pnpm desktop:pack
```

生成的 Windows 安装版和便携版位于 `release/`。推送 `v*` 标签时，仓库内的 Windows Release workflow 会构建两个安装包、生成 SHA-256 校验文件并上传到 GitHub Release。

## 项目结构

```text
src/client/       桌面工作台界面
src/desktop/      Electron 房主服务、安全存储和 Codex 安装接入
src/companion/    本地扫描、MCP bridge 和 Codex Hook 自动协调
src/server/       房间协议、REST/MCP、SQLite 与发布门禁
src/shared/       公共协议类型
docs/             架构与接入补充资料
```
