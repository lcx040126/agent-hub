# Agent Hub v0.2.0 发布说明

> 本说明明确区分已经通过的自动化/打包验证与尚未进行的真实安装、多机和升级验证。未列为通过的项目不得视为已经验收。

v0.2.0 重点解决多人使用 Agent 协作时的三个问题：减少不必要的写入阻塞、保护已经完成的功能逻辑，以及让真正需要协调的冲突能够及时通知到相关成员。

## 产品原理

房主电脑运行 Agent Hub 房间服务并保存 SQLite 数据库，每位成员的桌面客户端、本地扫描器和 Codex 都连接到这个房间。MCP 负责让 Codex 按需读取共享上下文和执行协调操作；`SessionStart`、`PreToolUse`、`PostToolUse`、`SessionEnd` 四类 Hook 负责在 Agent 工作的关键时点自动检查。

房间共享的是成员、会话、工作范围、项目结构、功能行为、决定、验证、风险和 Git 证据等结构化事实，不会合并模型内部记忆，也不会上传私人聊天或隐藏思考。

v0.2.0 把保护分成两层：实时租约处理“别人现在正在改什么”，历史功能记忆处理“别人以前已经完成了什么”。房主关闭普通红色阻塞时，手动独占租约和历史功能修改确认仍然有效。

## 本版新增

### 1. 重叠范围分为黄色警告和红色阻塞

文件或目录范围发生重叠时，不再全部阻止后来的 Agent：

- 黄色警告会显示重叠成员、路径和原因，但 Agent 可以继续工作。
- 红色阻塞会在写入前停止 Agent，并进入协调流程。
- 每次实际写入具体文件时都会重新判断，宽泛的目录租约不会掩盖内部关键文件。
- Luban 源表、生成文件和相关目录默认只显示黄色警告，房主也可以改为红色阻塞。

黄色警告只表示“这里可能需要留意”，不会自动证明代码一定冲突；红色阻塞表示当前规则要求先完成协调。

### 2. 房主可临时关闭普通红色阻塞

房间新增“关键范围阻塞保护”开关：

- 开启时，按房间当前文件风险策略显示黄色警告或红色阻塞。
- 关闭时，自动租约和普通工作范围的重叠全部降为黄色警告，适合集中合并或协作频繁的时段。
- 手动独占租借和历史功能修改确认不会因为关闭该开关而失效。

只有房主可以切换；其他成员可以查看当前状态。切换会立即影响后续检查，但不会删除已有租约。

### 3. 已完成功能形成可复用记忆

Agent 完成一项功能后，Agent Hub 会结合任务目标、实际改动、代码符号、Git 证据和验证结果形成结构化功能记忆，包括：

- 已实现的用户行为和不应被意外改变的行为约束。
- 关联文件、类、方法、公开接口、Unity 资源、依赖和测试。
- 提交状态、验证结果、剩余风险和后续修改历史。

后来开发相关系统时，Agent 会自动取得最相关的少量记忆，而不是把房间全部历史一次性塞入上下文。普通任务默认读取每项功能当前有效的版本；草稿、候选和冲突版本只显示状态，需要排错或审计时才展开旧版本。

如果新的写入明确影响了已有功能，Codex 会先在当前对话中说明受影响的行为、符号和路径，并询问当前成员是否确认修改。未经明确确认不会继续；确认只对当前会话和批准范围有效。修改完成后需要重新验证关联行为并形成新的功能版本，旧版本不会被删除。

### 4. 红色阻塞自动发送释放申请

Agent 因红色冲突被阻塞后，Agent Hub 会自动向租约持有人发送申请，不需要请求方再到其他聊天工具中寻找对方。

- 租约持有人可通过 Windows 通知和应用内待处理窗口查看申请。
- 申请会去重并持久保存；成员离线时不会被自动视为同意，重新连接后仍可处理。
- 普通租约可以交出实际发生冲突的路径，其余未冲突路径继续保留。
- 同意后的释放和申请人领取在服务端一次完成，避免中间被第三方抢占。
- 黄色警告不会创建释放申请。

自动租约默认在停止活动 10 分钟后过期。房主可选择 5、10、15、30 或 60 分钟；持续工作的 Agent 通过心跳保持租约。普通状态最后一次真实 Hook 活动超过 5 分钟后停止心跳；正在执行的单次写入可在构建、测试或 Unity 运行期间继续续期，但最长 2 小时，避免异常退出的 Codex 永久占用范围。

### 5. 人工和外部程序的改动不参与执法

Agent Hub 只检查能够可靠归因到当前 Agent 工具调用的写入。以下变化不会创建租约、房间风险、黄色警告或会话隔离：

- 成员通过编辑器手工修改的文件。
- Unity、IDE 或其他程序的自动保存。
- 无法可靠归因到当前 Agent 调用的外部变化。

这些变化仍然属于用户已有工作，Agent 不得擅自覆盖、删除或回滚。若人工和 Agent 同时修改同一个明确目标文件，系统无法可靠区分每一行的来源，因此该文件仍按 Agent 写入检查，并提醒 Agent 保留已有用户改动。

本版同时修复 PowerShell 参数被误认为文件路径的问题，例如变量、`-LiteralPath`、`Directory` 或 `Junction` 不再被登记成租约路径。Agent 自己发出的写命令如果无法确认真实目标，仍会在执行前停止，不能借“外部变化”绕过保护。

### 6. 房主可自定义文件风险策略

房主可在设置中决定哪些重叠只警告、哪些必须阻塞：

- 提供普通源码、Unity 场景与 Prefab、Unity 序列化资源、项目设置、Git/CI、结构化配置和 Luban 等预设分类。
- 支持按扩展名、具体项目相对文件和项目相对目录添加规则，不需要编写正则表达式。
- 匹配顺序为：具体文件、最长匹配目录、扩展名或预设分类、默认黄色。
- 每次保存形成新的策略版本，并记录操作者、时间和变更内容。

其他成员可以查看当前策略和判定原因，但只有房主可以编辑、删除或恢复默认规则。该策略只控制实时范围重叠，不会关闭历史功能修改确认或削弱手动独占租借。

### 7. 手动独占租借文件或目录

原“手动领取工作范围”窗口新增两种模式：普通工作范围和独占保护范围。

任何房间成员都可以独占一个或多个项目相对文件或目录，租期可在 5 分钟到房主设置的上限之间选择；房间默认上限为 24 小时。独占租期是固定时间，不会被 Agent 心跳自动延长，需要继续保护时由租客主动续租。

独占范围内：

- 租客本人名下的 Agent 可以直接写入；租客自己的其他 Agent 会话只收到黄色提醒。
- 其他成员的 Agent 无论修改哪种文件都会先被红色阻塞，包括 Luban 文件，也不受“关键范围阻塞保护”开关影响。
- 租客可批准、拒绝或查看申请详情。
- 一旦批准，即结束整份独占租约，而不是只释放申请涉及的单个文件或子目录；申请人只会取得自己实际请求的范围。
- 租客离线时独占租约继续保留到固定到期时间，待处理申请不会自动获批。

手动独占租借只约束已接入 Agent Hub Hook 的 Agent，不能阻止成员通过 IDE、Unity 或其他方式人工修改文件。

### 8. 所有客户端自动检查并一键更新

从 v0.2.0 开始，每个已安装客户端都会在启动后和运行期间检查 GitHub Release：

- 发现新版本时显示版本号、更新说明、下载大小以及“立即更新”和“稍后”。
- 只有用户点击“立即更新”后才下载、校验、安装并重启，不会在工作过程中擅自重启。
- 更新包会校验 HTTPS 来源、数字签名、文件大小和 SHA-256；不可信、被篡改、降级或协议不兼容的包不会运行。
- 更新覆盖桌面界面、房间服务、本地扫描组件、MCP bridge 和 Codex Hook，避免客户端与服务端处于混合版本。
- 普通成员只重启自己的客户端；房主更新时房间服务会短暂重启，其他成员随后自动重连。

每位成员仍在自己的电脑上确认更新。房主电脑不会代替其他成员下载或安装客户端。

v0.2.0 只发布 `AgentHub-Setup-0.2.0-x64.exe` NSIS 安装版，不再发布 Portable 便携版。更新器固定信任 `lcx040126/agent-hub` 的稳定版 GitHub Release，并拒绝降级、同版本清单替换以及协议或数据库结构不兼容的更新。

## 安装与首次使用

1. 房主和每位成员从本次 GitHub Release 下载 `AgentHub-Setup-0.2.0-x64.exe`，并使用 `SHA256SUMS.txt` 核对文件。
2. 房主选择本机 Git 项目创建房间，把局域网邀请地址和房间码发给成员，并在协作期间保持 Agent Hub 运行。
3. 成员选择自己电脑上的同一 Git 项目，填写邀请地址和房间码加入。本地绝对路径可以不同。
4. 每位成员在“连接设置”中点击“安装连接”，完全重启 Codex。
5. Codex 首次加载时，核对并信任 Agent Hub 的四类非托管 Hook；未经信任的 Hook 不会执行，自动保护也不会完整生效。
6. 从已连接项目目录创建 Codex 任务。项目外任务不会自动匹配房间，即使后来在命令中临时指定另一个目录也不会改变会话归属。

加入房间后，成员可以读取加入前已经保存的结构化记录。房间码不提供 GitHub 仓库写权限，仓库协作者和分支保护仍需在 GitHub 单独设置。

## 典型使用方式

1. 房主创建或打开房间，在设置中检查“关键范围阻塞保护”、自动租期和文件风险策略。新房间可以先使用默认策略。
2. 成员加入房间并保持 Agent Hub Hook 与 MCP 连接。正常开发时无需手工维护租约或功能记忆。
3. 普通重叠出现黄色警告时，成员可结合路径和任务内容自行判断；关键重叠出现红色阻塞时，系统会自动发送释放申请。
4. 明确需要暂时保护某个文件或目录时，在“手动领取工作范围”中选择“独占保护范围”并设置固定到期时间。
5. 功能完成后，Agent Hub 记录当前功能版本。以后修改相关类、方法、接口或测试时，Codex 会先说明影响；当前成员确认后才能在批准范围内继续。
6. 工作繁忙且希望减少普通阻塞时，房主可以暂时关闭关键范围阻塞保护；手动独占和历史功能确认仍然有效。

## 从 v0.1.0 升级

### v0.1.0 需要最后一次手动安装

v0.1.0 本身没有能够更新完整客户端的一键更新器，因此房主和每一位成员都必须从本次 GitHub Release 手动下载并安装 v0.2.0 一次。不能等待 v0.1.0 自动升级到本版。

完成这次手动安装后，后续版本才会由 v0.2.0 客户端自动检查，并在用户点击“立即更新”后完成一键升级。

建议升级顺序：

1. 先暂停新的 Agent 写入任务，等待正在执行的工具调用结束。
2. 房主先退出 Agent Hub，再按 Release 资产说明安装 v0.2.0；不要主动删除 Agent Hub 的用户数据或房间数据库。
3. 房主确认原房间可以打开后，再让其他成员逐台退出旧客户端并安装 v0.2.0。
4. 所有成员重新打开客户端，检查原房间连接、项目连接和客户端版本状态。
5. 如果 Codex 明确提示 Hook 命令发生变化，再按提示重新审核 Hook 信任；普通升级不应要求重新加入房间。

首次手动升级的安装方式、兼容检查和数据迁移状态，请以文末“验证结果”为准；列为尚未验证的项目不能当作已经通过。

## 数据保留与回退

v0.2.0 的升级流程设计为保留：

- 房间和成员连接信息。
- 活动租约、待处理申请和房间协作记录。
- 功能记忆及其版本历史。
- 本机成员凭证、项目连接和房间设置。

房主通过 v0.2.0 及后续客户端发起应用内更新时，会先使用 SQLite 一致性备份机制保存房间数据库。本机连接配置和 DPAPI 凭证位于安装目录之外的 Electron 用户数据目录，安装器不应覆盖它们；当前版本没有为这些配置再制作一份独立备份。

应用内更新准备期间会保留上一份已确认可运行的安装包、目标安装包和本次数据库备份。恢复守护成功布防后，目标版本必须依次通过界面、房间服务/数据库、MCP bridge 和 Codex Hook 健康检查，才提交更新结果并清理不再需要的旧缓存和临时备份。清理程序文件不会主动删除房间数据库、功能记忆、成员连接或本机加密凭证。

房主更新造成的短暂断线不会自动释放现有租约，也不会把成员工作错误标记为结束。即便如此，首次从 v0.1.0 手动升级前仍建议选择没有 Agent 正在写入的时间窗口，并且不要手工删除旧数据目录。

## 已知边界

- Agent Hub 只能管理已正确接入 Hook 的 Agent，不能锁住键盘、IDE、Unity 或其他人工操作。
- 黄色警告不会阻止写入，也不代表系统已经替团队解决内容合并；团队仍需正常审查 Git 差异并处理语义冲突。
- Windows 通知是提醒入口，最终申请和租约状态以房主服务为准。客户端未运行时不会即时显示桌面通知，但申请会保留到重新连接。
- 普通释放申请只在红色阻塞时生成；黄色警告不会打扰租约持有人。
- 手动独占租约一经租客批准会整份结束，即使申请人只请求其中一个文件。
- 关闭关键范围阻塞保护只会降低自动租约和普通工作范围的重叠等级，不能绕过手动独占或已有功能修改确认。
- 功能记忆不是源码的替代品。Git、项目源码、配置源文件和人工批准的项目规则仍是最终事实来源。
- 未提交、验证失败或证据不足的功能修订只会保持草稿、候选或待验证状态，不应被当作已经稳定的功能。
- Unity 序列化资源等内容无法始终精确到代码符号，影响判断可能退化为文件或资源范围，并说明触发原因。
- 人工和 Agent 同时修改同一个明确目标文件时，Agent Hub 无法可靠按行区分来源；该文件仍按 Agent 写入规则检查。
- 房主电脑承担房间服务时，房主电脑或网络不可用期间，其他成员无法取得最新房间状态；离线期间不会自动批准释放申请。
- 自动更新从 v0.2.0 才开始生效，并且每台客户端都需要各自确认。选择“稍后”不会强制重启，但协议不兼容时可能必须先更新才能继续连接。
- 这里的“自动更新”是下载、校验、安装并重启客户端，不是运行中无重启替换程序。
- 安装到 D 盘只改变程序安装位置；Electron 用户数据、房间数据库和更新恢复缓存通常仍位于 `%APPDATA%\Agent Hub` 等当前 Windows 用户目录中，通常占用 C 盘。
- 当前安装包没有商业 Authenticode 代码签名。Ed25519 签名保护的是更新清单，Windows SmartScreen 或安装界面仍可能显示“未知发布者”。
- 自动回退依赖旧客户端成功启动恢复守护，并依赖新客户端至少运行到健康检查失败。若安装过程中重启或新程序完全无法启动，当前没有独立的 RunOnce 恢复入口，可能需要人工重新安装或还原数据。
