# Agent Hub v0.2.8

Agent Hub v0.2.8 修复任务级租约范围事件接口无法通过桌面代理读取的问题，修复 PreToolUse Hook 放行格式兼容性问题，并精简实时会话中的重复标识信息。

## 问题修复

- 修复桌面代理未放行 `GET /api/leases/:id/scope-events`，导致租约范围历史在桌面端显示错误的问题。
- 为该接口允许 `limit` 与 `before` 分页参数，同时继续拒绝未知查询参数和任意未登记的 API 路由。
- 增加桌面代理路由回归测试，覆盖成功请求、分页查询和敏感参数拦截，避免服务端新增读取接口后再次出现客户端白名单不同步。
- 修复允许执行并附带提示时返回不受当前 Codex 支持的 `permissionDecision: "allow"` 组合；改为使用 `additionalContext` 传递提示，避免 Hook 错误和提示丢失。
- 修复桌面端 `spawn git ENOENT`：统一探测 PATH、Windows 标准 Git 安装目录和 UGit 内置 Git 路径；Git 不可用时显示安装、PATH 和重启指导。
- Git 解析覆盖项目选择、仓库扫描、Hook/提交证据与任务收尾，未改变租约、MCP、纯监测模式、protocol `2` 或 schema `6`。
- 纯监测模式继续放行普通写入，真实 `deny` 仍按保护规则阻止；租约领取、审计和 PostToolUse 归因流程不变。

## 界面优化

- 未领取租期的实时会话行不再常驻显示 Codex Session ID、Hub Session ID 和当前 Turn ID，也不再显示包含完整 ID 的自动生成会话占位文案。
- 实时会话行继续显示成员、客户端、分支和 `activityEpoch`，真实任务描述仍然保留；三类 ID 及复制按钮统一在领取租期后的任务卡中显示，历史调用归因继续保留对应 Turn ID。

## 兼容性与升级

- 应用版本为 `0.2.8`，协议版本保持 `2`，数据库 schema 保持 `6`，最低来源协议和 schema 保持 `1` 与 `2`。
- v0.2.7 用户应通过应用内更新升级到 v0.2.8；升级不需要重新加入房间，也不会删除房间数据库、连接凭证、Hook 或 MCP 配置。
- v0.2.7 的租约协调、范围审计和历史数据继续兼容；本版本只调整未领取租期时的 ID 展示，不改变会话、租约或审计数据。

## 已验证

- 桌面代理专项测试覆盖 `scope-events` 路由及 `limit`/`before` 查询参数，并确认未知参数仍被拒绝。
- 客户端回归测试确认未领取租期的实时会话行不再输出三类 ID，领取租期后的任务卡仍显示缩略 ID 和复制入口。
- 版本元数据、服务端健康版本、更新清单测试和打包迁移探针均已切换到 `0.2.8`。
- 两套 TypeScript 检查、62 个测试文件共 611 项串行全量测试、生产构建和 `git diff --check` 通过。
- Hook 回归测试确认 PreToolUse 的放行提示仅通过 `additionalContext` 返回，不再生成 `unsupported permissionDecision:allow`；纯监测模式放行和真实 `deny` 行为保持不变。
- 本地界面在 1264x710 桌面视口和 390x844 窄屏视口完成验证：实时会话行不显示 ID 且没有横向溢出，租期任务卡仍保留三类 ID。
- 发布前仍需由 Windows 发布流水线执行 NSIS 打包、更新恢复探针、签名清单和安装包校验。

## 动态数据保留与定时清理

- 服务启动后执行一次动态清理，之后每天执行一次；清理按房间分批、按事务提交，单个房间或批次失败只记录诊断并在下一周期重试，不影响协作请求。
- 普通扫描 `scan.recorded` 和无租约归属的 Hook 空范围审计保留 30 天；已结束、已释放或已过期租约的范围审计（`lease.scope_observed`、`lease.scope_expanded`、`lease.scope_covered`）保留 90 天。
- 决策、验证、交接、风险、冲突、租约与成员状态变更、释放申请以及提交/完成证据等高价值活动长期保留。
- 当前有效租约、未关闭或正在收尾的会话、待处理释放申请及其关联活动不会被清理。清理任务不生成新的活动记录，也不在请求期间执行全量 `VACUUM`，仅尽力运行轻量 `PRAGMA optimize`。
- 清理使用明确的活动类型白名单和实体关联保护，跨房间独立处理，重复运行幂等；历史分页继续遵循原有游标兼容和无效游标提示。
- 本功能不增加数据库字段、REST/MCP 字段或用户设置，protocol 仍为 `2`，schema 仍为 `6`，不改变租约生命周期、Hook、MCP、冲突判断或纯监测模式。
