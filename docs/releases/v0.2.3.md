# Agent Hub v0.2.3 未发布说明

> 当前状态：开发候选，尚未打包、创建标签或发布。本文件记录已经实现的范围和待验收项，不代表正式 Release 已可用。

v0.2.3 重新设计 Codex Hook 的结束流程和高频写入检查，目标是在不削弱红色冲突与历史功能保护的前提下，减少成员等待，并让超过 Codex 三秒生命周期的会话收尾工作可靠完成。

## 本版变更

### SessionEnd 快速返回

- Codex 配置中的 `SessionEnd timeout` 从不兼容的 60 秒改为平台允许的 3 秒。
- Hook 先把结束任务原子写入 Agent Hub 用户数据目录，再用最多 1.5 秒请求服务端开始最终处理。
- Hook 不再同步扫描 Git、收集验证、生成记忆、逐个关闭租约或关闭会话，自动化目标为 2.5 秒内返回。
- 队列不保存成员令牌和完整 diff；令牌只由持续运行的桌面端从 DPAPI 连接存储中按需读取。

### Stop 与 Git 提交后释放

- 新增无 matcher、`timeout = 3` 的 `Stop` Hook。它先持久化 completion operation ID、turn ID、activity epoch、自动租约和归因路径，再执行限时 Git 与服务端检查；所有路径都向 Codex 返回 `{"continue":true}`。
- 自动租约增加 `working` 和 `awaiting_commit` 阶段。回合结束后进入 `awaiting_commit` 并停止心跳续期；归因改动已完整进入本地 HEAD 或已经完全撤销时立即释放，否则保留到房间现有 TTL。
- 桌面 worker 每 15 秒只检查等待提交任务。它按任务归因路径核对 staged、unstaged、untracked、基线和 HEAD 内容；无关提交、部分提交、提交后继续修改、分支变化、归因截断和证据不完整都不会提前释放。
- 后续写入会先废止旧完成任务并递增 activity epoch，再恢复续租或重新领取；旧检查、响应丢失和网络重试不能释放新一轮租约。
- Agent Hub 只检测本地提交，不执行 `git commit`，不要求 `push` 或限定提交作者。手动普通和独占租约不受此流程影响。

### finalizing 状态与幂等处理

- 会话增加 `finalizing` 状态。进入后停止普通写入、心跳、续租、分支操作和 MCP 功能修改，但允许持有正确 `finalizationId` 的最终证据操作。
- 进入最终处理时不释放活动自动租约；`awaiting_commit` 继续等待提交或 TTL，尚未收到可信 `Stop` 的 `working` 自动租约也保留原到期时间作为兜底。手动普通和独占租约保持原状态与到期规则。
- 最终扫描按 `finalizationId` 去重；后台重复启动或响应丢失不会重复写入扫描。
- 功能记忆仍结合最终 Git 证明和真实验证记录决定草稿、候选或当前有效状态；重试会先识别同会话已有修订。
- 桌面重启后继续读取队列。网络故障使用指数退避；本地证据多次失败后关闭会话并留下唯一风险记录，不让会话永久卡住。

### 日常写入延迟

- `PreToolUse` 普通路径只读取仓库根目录、分支和 HEAD，不再重复扫描、读取并哈希所有脏文件。
- 分支同步、续租、冲突检查、历史功能影响和自动领取合并为一次服务端请求。
- `PostToolUse` 对 `apply_patch` 等明确目标只扫描目标路径；生成器、格式化器和无法确定副作用的命令仍使用完整扫描保证归因正确。
- 黄色重叠保持提醒但不阻塞；红色冲突和历史功能修改确认继续在写入前同步阻止。

### 安装升级后的自动校正

- 安装版 Agent Hub 每次启动都会在后台检查曾经授权安装的 Codex 接入，不阻塞启动健康确认；它会自动补回缺失的 MCP 和当前版本全部受管 Hook，并把旧命令、旧 runner 路径、错误参数和旧 Hook 配置替换为当前版本。
- v0.2.2 的 `SessionEnd timeout = 60` 会被识别为旧受管处理器并替换为唯一的 3 秒处理器，不会在升级后与新处理器重复执行。
- 连接存储新增三态 Codex 安装意图：旧版本未知、明确安装、明确不安装。旧状态只有在当前配置中发现可证明属于 Agent Hub 的 MCP 时才迁移为已安装；从未授权或已经明确移除的房间不会被擅自写回。
- 启动、手动安装、房间删除和桌面更新安装共用串行生命周期队列。安装或删除会先保存意图，配置失败后由下次启动补偿；安装器启动后拒绝新的 Codex 安装和房间删除操作。
- 每次对账从同一文件快照发现并合并；外部同时修改配置时最多重读重合并 3 次，再以临时文件原子替换。无变化路径也会复核快照，但不会改文件、创建备份或要求重启 Codex。
- 只有同时满足 Agent Hub 派生名称、可执行文件名、当前 user-data 路径、runner 后缀、Node 模式环境变量及唯一 bridge/connection 参数的 MCP 才会作为遗留项清理；Hook 也必须匹配预期程序、完整 launcher 路径和事件。其他 MCP、用户 Hook 和无法确认归属的相似条目保持不变。
- 用户 TOML 损坏或不可写时保留原文件并记录启动警告，下次启动继续重试，但不会把桌面更新判定为启动失败。

## 兼容性

- 应用版本：`0.2.3`
- 协议版本：1
- 数据库 schema：4
- 最低可读取来源 schema：2

schema 4 为会话和最终扫描增加最终处理字段与唯一索引。正式更新前必须验证从 schema 3 原位迁移、更新失败时数据库恢复，以及旧客户端不得打开已经迁移到 schema 4 的数据库。
