# Agent Hub v0.2.3 未发布说明

> 当前状态：开发候选，尚未提交、打包或发布。本文件记录已经实现的范围和待验收项，不代表正式 Release 已可用。

v0.2.3 重新设计 Codex Hook 的结束流程和高频写入检查，目标是在不削弱红色冲突与历史功能保护的前提下，减少成员等待，并让超过 Codex 三秒生命周期的会话收尾工作可靠完成。

## 本版变更

### SessionEnd 快速返回

- Codex 配置中的 `SessionEnd timeout` 从不兼容的 60 秒改为平台允许的 3 秒。
- Hook 先把结束任务原子写入 Agent Hub 用户数据目录，再用最多 1.5 秒请求服务端开始最终处理。
- Hook 不再同步扫描 Git、收集验证、生成记忆、逐个关闭租约或关闭会话，自动化目标为 2.5 秒内返回。
- 队列不保存成员令牌和完整 diff；令牌只由持续运行的桌面端从 DPAPI 连接存储中按需读取。

### finalizing 状态与幂等处理

- 会话增加 `finalizing` 状态。进入后停止普通写入、心跳、续租、分支操作和 MCP 功能修改，但允许持有正确 `finalizationId` 的最终证据操作。
- 自动和普通租约在开始最终处理时释放，手动独占租约继续遵守原有固定到期/人工交接规则。
- 最终扫描按 `finalizationId` 去重；后台重复启动或响应丢失不会重复写入扫描。
- 功能记忆仍结合最终 Git 证明和真实验证记录决定草稿、候选或当前有效状态；重试会先识别同会话已有修订。
- 桌面重启后继续读取队列。网络故障使用指数退避；本地证据多次失败后关闭会话并留下唯一风险记录，不让会话永久卡住。

### 日常写入延迟

- `PreToolUse` 普通路径只读取仓库根目录、分支和 HEAD，不再重复扫描、读取并哈希所有脏文件。
- 分支同步、续租、冲突检查、历史功能影响和自动领取合并为一次服务端请求。
- `PostToolUse` 对 `apply_patch` 等明确目标只扫描目标路径；生成器、格式化器和无法确定副作用的命令仍使用完整扫描保证归因正确。
- 黄色重叠保持提醒但不阻塞；红色冲突和历史功能修改确认继续在写入前同步阻止。

- 协议版本：1
