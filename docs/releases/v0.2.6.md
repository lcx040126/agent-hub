# Agent Hub v0.2.6

> 状态：源码候选，尚未发布。本文没有正式安装资产、哈希、签名、标签或 GitHub Release 审计。

v0.2.6 将风险颜色与执行决定分离，并让房主可以把自动与普通协作保护切换为纯监测模式，同时保留跨成员手动独占授权。

## 风险与决定

- `severity=warning` 显示黄色普通警告，`severity=blocking` 显示红色高风险警告。
- 只有 `decision=deny` 表示对应写入或领取已被阻止；红色高风险与 `decision=warn` 可以同时出现并允许继续。
- 客户端按 severity 着色，按 decision 显示“已阻止”和统计阻塞数。MCP 与发布门禁也不再把 blocking severity 单独视为拒绝。
- 实时租约只为 deny 冲突创建释放申请。

## 纯监测模式

- 房主关闭写入阻塞保护后，自动与普通范围仍按规则显示黄色或红色风险，但不会因这些重叠阻止写入。
- 历史功能修改确认在纯监测模式下改为建议：Agent 仍需报告影响和风险，但未确认不再构成写入门槛。
- 其他成员已经持有的手动独占范围仍需持有人批准，这是纯监测模式下保留的唯一普通写入 deny。
- 同一成员的其他 Agent 命中自己的手动独占时显示红色高风险警告，但允许写入。新建手动独占范围与任一活动租约重叠时仍可拒绝领取。
- 切换时会解除旧自动阻塞围栏并取消不再适用的非独占释放申请，不删除现有租约或等待提交生命周期。
- 待处理的手动独占申请及各自的 deny 证据在切换后保留；重新开启保护会清理旧模式的普通冲突投影，由下一次实时检查按当前成员、策略和租约状态重建决定。因切换而取消的普通申请不受旧冷却记录抑制，下一次真实拒绝会重新创建可审批申请。

## 协议与升级

- 应用版本：`0.2.6`；协议版本：2；数据库 schema：5。
- 最低来源协议：1；最低来源 schema：2。协议升级不要求新的数据库迁移。
- 开启纯监测模式前，房间内所有现有成员都必须上报协议 2。界面提前列出旧协议或未上报协议的成员，服务端在保存时再次校验。
- 纯监测房间拒绝协议不匹配或未上报协议的新成员加入。升级期间应先保持写入阻塞保护开启，让所有成员升级并重新连接，再由房主切换。
- 升级不得先卸载 Agent Hub，也不要删除 `%APPDATA%\agent-hub` 或房间 SQLite 数据库。

## MCP 与发布门禁

- MCP 工作流明确说明：租约冲突只有 `decision=deny` 才停止；blocking severity + warn 是可写的高风险警告。
- 写入阻塞保护开启时，历史功能确认仍按原流程执行；纯监测模式下只作建议。
- `gate:publish` 从房间快照读取 `settings.blockingProtectionEnabled`，并以仪表盘中的同一设置作为回退。
- 设置明确为 `false` 时，门禁仍输出 deny 冲突、未解决 critical 风险和最新失败验证，但退出码为 0。快照不可用时也只有仪表盘明确为 `false` 才允许仅报告；仪表盘为 `true` 或无法确认时返回退出码 2 并保持默认拒绝。
