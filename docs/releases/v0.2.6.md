# Agent Hub v0.2.6

Agent Hub v0.2.6 separates risk severity from execution decisions, adds monitor-only coordination, and repairs Hook session lifecycle across multiple prompts in one Codex task.

## 新增内容

- Risk `severity` controls yellow/red presentation; only server `decision=deny` stops a write or lease acquisition. A red `blocking` severity with `decision=warn` remains a writable high-risk warning.
- Room owners can disable write blocking for monitor-only coordination. Automatic overlaps and historical feature confirmation remain visible as warnings; an existing cross-member manual exclusive denial remains enforceable.
- MCP tools accept both MCP-created sessions and active Codex Hook sessions for coordination operations.

## 问题修复

- MCP no longer closes a Hook-owned session. Calling `session_close` for `source=codex-hook` returns HTTP 409 `hook_session_lifecycle_owned` without changing the session or releasing its leases. MCP fallback sessions created by `session_open` retain normal close behavior.
- MCP instructions now require Hook sessions to reuse the SessionStart `session.id`, record results with feature revisions and events, and leave final closure to `SessionEnd`.
- Hook `/api/sessions` responses are validated for `session.id`, `status`, `reused`, `currentTurnId`, and `activityEpoch`. A replacement ID creates a new generation with a new finalization ID, a fresh Git baseline, and no inherited leases, pending writes, attribution, waiting fences, quarantine, or completion state.
- A same-generation response only synchronizes turn and activity epoch. Stale-epoch recovery uses the shared adoption flow and sends the retrying `/api/edits/prepare` request to the adopted ID. Invalid or non-active replacement responses keep protection-mode writes denied with a diagnostic reason.
- Old SessionEnd, completion, and heartbeat work remains fenced by the old session and finalization identifiers, so late results cannot overwrite the new generation.

## 兼容性与升级

- Application version is `0.2.6`; protocol version is `2`; database schema remains `5`; minimum source protocol and schema remain `1` and `2`.
- No database migration or MCP input shape change is required. Existing MCP clients that try to close a Hook session now receive the documented 409 response; the active Hook session is preserved.
- Do not uninstall Agent Hub or delete `%APPDATA%\agent-hub` during upgrade.
