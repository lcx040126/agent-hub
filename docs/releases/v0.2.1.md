# Agent Hub v0.2.1 发布说明

> 本说明明确区分已经通过的自动化验证与尚未进行的真实安装、多机和自动更新验证。未列为通过的项目不得视为已经验收。

v0.2.1 解决一个直接影响日常开发的问题：成员已经退出房间或真正关闭 Agent Hub 后，已安装在 Codex 中的 Hook 和 MCP 不应继续访问房间、注入上下文、提示冲突或阻止写入。

本版没有删除 Codex 连接配置，而是在本机增加持久化连接开关和运行哨兵。这样既能让退出立即生效，又能让未主动退出的成员在 Agent Hub 重启后自动恢复，不必重复安装 Hook 或 MCP。

## 本版新增

### 1. 退出房间后立即隔离 Codex 接入

每个已保存连接增加 `integrationEnabled` 状态。成员退出房间时，只暂停所选连接：

- 本机 Hook 立即静默，不连接房间、不创建会话、不注入上下文、不记录活动、不显示冲突，也不阻止写入。
- MCP bridge 不建立远端连接，向 Codex 返回空工具列表。
- 本机仍保留成员身份、DPAPI 加密凭证、项目连接、房间历史和设置。
- 重启 Agent Hub 后，该连接仍保持暂停；成员主动重新启用后，Hook 可建立新会话，MCP 在下次工具请求时自动重连。

旧版 `connections.json` 没有 `integrationEnabled` 字段时按 `true` 读取。连接、令牌和暂停状态通过串行写入保存，避免并发操作丢失凭证或覆盖新状态。

### 2. 使用运行哨兵判断后台是否真实存活

桌面后台维护本地运行哨兵，记录实例 ID、PID、状态和心跳时间，默认约每 5 秒原子刷新。

出现以下任一情况时，Hook 和 MCP 将本机接入视为 inactive：

- 哨兵文件缺失或内容损坏；
- 哨兵记录的进程已经退出；
- 状态为 `stopped` 或 `maintenance`；
- 心跳超过约 30 秒没有更新。

因此程序异常崩溃、进程被强制结束或后台意外停止后，即使 Codex 配置中仍保留稳定 Hook launcher，本机接入也会在最多约 30 秒后停止影响 Codex。异常崩溃不会承诺远端自动释放手动独占租约；普通租约仍按房间的到期规则处理。

### 3. MCP 本地握手与远端连接分离

MCP bridge 先在本机完成初始化，只有 Codex 实际查询工具时才懒连接房间服务。

- 连接暂停或哨兵 inactive 时，不访问房间，工具列表为空。
- 房间断网或暂时不可用时，本地 MCP 进程仍保持可用，工具列表为空。
- 连接和房间恢复后，下一次请求重新建立远端连接并刷新工具列表。
- 已连接的远端异步断开时立即刷新工具列表；网络错误、HTTP 408、429 和 5xx 自动重试，HTTP 401/403 则停止轮询并给出明确的凭证或权限诊断。

这避免了房间离线时 Codex 因 MCP 启动失败而持续受到影响。

### 4. 幂等暂停与本地清理重试

房间服务新增认证接口 `POST /api/member/pause`，请求包含 `reason`、`cutoffAt` 和 `requestId`。服务端在一个事务中：

- 使用房间服务器首次处理请求时的服务器时间作为实际清理边界，关闭当时可见的本人活动会话；
- 释放本人的全部自动、普通和手动独占租约；
- 取消相关待处理释放申请；
- 使相关功能修改确认过期；
- 写入可审计记录。

`cutoffAt` 是客户端生成的请求身份参数，不会直接与服务器生成的会话时间比较。同一成员使用同一 `requestId` 和相同参数重试时不会重复执行；如果参数不同，服务端返回冲突。实际清理边界始终来自房间服务器自己的时钟，因此客户端时间明显落后或领先都不会改变首次清理范围。

网络异常时，客户端先让本机 Hook/MCP 失效，再把未完成清理写入本地重试队列。后续重试沿用原始 `cutoffAt` 和 `requestId`。只要待清理记录仍存在，Hook、MCP、后台扫描、Codex 心跳和桌面写请求都不会创建新远端状态；清理成功后才自动恢复，所以服务器首次处理旧请求时不存在需要保留的新会话或租约。

Hook、MCP 和后台扫描使用跨进程操作标记保护“本地检查到远端请求”之间的窗口。暂停意图先持久化并关闭本地闸门，再等待已登记操作结束，之后才固定幂等请求参数；存活进程的标记不会因为运行时间较长被误删。等待有明确超时，超时后保留持久化意图且不会发送不安全的远端暂停请求。后台扫描也有检查超时，并在每次远端请求前重新确认连接仍启用。

暂停只清理活动协作状态，不删除成员身份、令牌、房间历史、SQLite 数据库或功能记忆。

### 5. 网络故障不再误阻止 Codex 写入

网络超时、断网、HTTP 408、429 和 5xx 被视为暂时性软失败。Hook 会允许本次写入并给出黄色诊断，提醒当前无法完成实时协作检查。

以下情况不属于软失败，仍按明确的协调或安全错误处理：

- 真实租约重叠或历史功能修改确认；
- 分支变化导致的会话冻结或隔离；
- 身份认证失败；
- 本机成员凭证缺失、损坏或无法解密。

允许网络软失败意味着离线期间无法获得最新协作状态，不代表写入已经通过跨成员兼容性检查。恢复后仍需检查差异、运行测试并处理冲突。

## 桌面状态说明

| 操作或状态 | Hook/MCP | 会话和租约 | 房间数据 |
| --- | --- | --- | --- |
| 退出房间 | 暂停所选连接 | 尝试立即清理本人状态；失败则本地重试 | 保留 |
| 关闭主窗口 | 继续运行，窗口隐藏到托盘 | 不清理、不释放 | 保留 |
| 托盘“退出” | 先暂停全部本机连接，再停止后台 | 尝试清理服务器首次处理时可见的本人会话和全部本人租约 | 保留 |
| 房主退出 | 先暂停并清理房主本人，再停止本地房间服务 | 其他成员暂时离线 | SQLite 和历史保留 |
| 安装更新 | 进入 `maintenance`，暂时停用 | 不关闭会话，不释放租约 | 保留；失败回退后恢复 |
| 异常崩溃 | 哨兵过期后静默停用 | 不保证清理手动独占租约 | 保留 |

窗口右上角关闭按钮不等于退出 Agent Hub。需要真正停止后台时，应使用系统托盘菜单中的“退出”。

退出房间时，是否停止本地房间服务只依据服务端刚返回的当前成员角色。界面传入的布尔值、旧版连接缺失的角色以及本地缓存角色都不能授权停服；房主转移、离线、鉴权失败或角色查询失败时会保守地保持服务运行。

## 兼容性与数据保留

v0.2.1 保持：

- Agent Hub 协议版本 1；
- SQLite schema 版本 3；
- v0.2.0 的房间数据库和 `connections.json` 读取兼容性；
- Codex 配置中的稳定 Hook launcher 路径；
- 房间、成员、项目连接、加密凭证、风险策略、协作记录、功能记忆和历史修订。

主动退出会释放房间服务器首次处理时可见的本人活动租约，包括手动独占租约；待清理期间不会创建新远端状态，恢复后新建的租约不受旧清理请求影响。异常崩溃则不承诺自动远程释放手动独占租约。这两个行为是有意区分的。
