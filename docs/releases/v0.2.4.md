# Agent Hub v0.2.4

v0.2.4 修复旧房间数据库升级失败、后台扫描 metadata 超限，以及桌面进程在输出管道失效时可能被日志告警终止的问题。更新不改变协议版本或数据库 schema 版本。

## 新增内容

- 桌面端新增本机 UTF-8 JSONL 诊断日志，默认写入 `%APPDATA%\agent-hub\logs\desktop.log`。单文件最多 2 MiB，保留 3 个轮转文件。
- 日志只记录时间、级别、来源和错误的名称、代码、消息、堆栈；令牌、请求头、环境变量和扫描正文不会写入日志。
- 扫描 metadata 新增依赖与规则哈希的原始总数、实际上传数和截断标记，便于确认大仓库快照是否经过容量收敛。

## 问题修复

- 修复 v0.2.3 从 schema 3 升级时先创建 `local_scans(finalization_id)` 索引、后补 `finalization_id` 字段，导致 SQLite 报错并回滚整个迁移、Agent Hub 无法启动的问题。迁移现在先幂等补齐字段，再创建索引；失败回滚或手工补列后的数据库都可安全重试。
- 修复后台扫描只按 500 条依赖固定截断、却未遵守服务端 32,000 字符 metadata 上限的问题。扫描端与服务端现在共享同一上限，并按最终 `JSON.stringify(metadata).length` 保留规则哈希和依赖的稳定前缀；固定 metadata 自身异常超限时会在本机受控失败，不发送非法请求。
- 修复 Electron 主进程继承的 `stdout`/`stderr` 管道失效后，`console.error` 触发 `EPIPE` 并终止桌面进程的问题。流保护在桌面生命周期启动前安装，服务子进程输出直接写入诊断日志，日志写入、轮转或关闭失败均静默降级。

## 兼容性与升级

- 应用版本：`0.2.4`
- 协议版本：1
- 数据库 schema：4
- 最低可读取来源 schema：2

数据库迁移覆盖 v0.1.0 的 schema 2，v0.2.0/v0.2.1/v0.2.2 的 schema 3，v0.2.3 失败回滚后的 schema 3，已经手工补齐 `finalization_id` 但 `user_version` 仍为 3 的恢复状态，以及已迁移的 schema 4 和全新数据库。

- v0.2.2：可直接使用应用内更新。
- v0.2.0/v0.2.1：下载 `AgentHub-Setup-0.2.4-x64.exe`，在原安装目录手动覆盖安装。
- 无法启动的 v0.2.3：必须手动覆盖安装 v0.2.4，因为应用内更新入口不可用。
- 已修复或已正常迁移到 schema 4 的 v0.2.3：可正常使用应用内更新。

所有情况都不要先卸载 Agent Hub，不要删除 `%APPDATA%\agent-hub`，也不要手工删除房间 SQLite 数据库。覆盖安装会保留房间、成员、连接、凭证、租约、扫描和功能记忆。
