# Agent Hub v0.2.4

v0.2.4 是一个范围严格受限的数据库升级热修复，只处理旧房间数据库升级到 schema 4 时的启动失败，不包含错误日志、watchdog 或其他功能改造。

> 当前仅准备本地候选，尚未推送、打标签或发布。以下升级入口应在 v0.2.4 正式发布后使用。

## 问题修复

- 修复 v0.2.3 从 schema 3 升级时先创建 `local_scans(finalization_id)` 索引、后补 `finalization_id` 字段，导致 SQLite 报错并回滚整个迁移、Agent Hub 无法启动的问题。
- 迁移现在先检查并补齐 `local_scans.finalization_id`，再幂等创建 `scans_finalization_idx`。已失败并回滚到 schema 3 的数据库可直接重试。
- 已经手工补列但 `PRAGMA user_version` 仍为 3 的数据库也可继续完成迁移，不会重复添加字段或丢失已有 `finalization_id` 数据。

## 兼容性

- 应用版本：`0.2.4`
- 协议版本：1
- 数据库 schema：4
- 最低可读取来源 schema：2

自动化迁移覆盖以下正式历史状态：

- v0.1.0 的 schema 2；
- v0.2.0、v0.2.1、v0.2.2 共用的 schema 3；
- v0.2.3 升级失败、事务回滚后留下的 schema 3；
- 已手工补齐 `finalization_id`、但 `user_version` 仍为 3 的恢复状态；
- 已成功升级的 schema 4 和全新数据库。

每种升级都检查房间、成员、会话、租约和扫描记录保留，最终 `user_version=4`，目标字段与索引存在，并通过 SQLite `integrity_check` 和 `foreign_key_check`。

## 升级方式

- v0.2.2：v0.2.4 正式发布后可直接使用应用内更新。
- v0.2.0/v0.2.1：必须下载 `AgentHub-Setup-0.2.4-x64.exe`，在原安装目录手动覆盖安装。
- 无法启动的 v0.2.3：必须手动覆盖安装 v0.2.4，因为应用内更新入口不可用。
- 已修复或已正常迁移到 schema 4 的 v0.2.3：可正常使用应用内更新。

所有情况都不要先卸载 Agent Hub，不要删除 `%APPDATA%\agent-hub`，也不要手工删除房间 SQLite 数据库。覆盖安装的目的正是保留房间、成员、连接、凭证、租约、扫描和功能记忆。
