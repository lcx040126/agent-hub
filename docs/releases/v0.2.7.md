# Agent Hub v0.2.7

Agent Hub v0.2.7 将同一 Codex 任务中的 MCP 与 Hook 范围统一为一份 Agent 托管租约，并为团队决定增加可追溯的当前版本与替代历史。

## 新增内容

- 同一 Hook session、分支和 Git 基线下，MCP `lease_acquire` 与 Hook 自动领取复用一份任务级 Agent 托管租约。后续工具调用发现新的真实仓库路径时，原子扩展同一租约的路径并集，并保留调用级审计。
- “实时工作”任务卡显示可复制的 Codex Session ID、Hub Session ID 和当前 Turn ID；同一任务跨多轮只更新当前 Turn，不创建重复任务卡，历史 Turn 仍可从调用记录追溯。
- 当前决定可以通过界面“更新决定”、REST `POST /api/decisions/:id/supersede` 或 MCP `event_append(eventType="decision")` 显式替代。新决定成为当前版本，旧决定保留为已替代历史。
- 默认决定计数、协作记录列表和 Agent 相关上下文只使用当前决定；成员可以按新到旧查看已载入的替代链、作者、时间和判断依据，记录窗口未包含更早版本时会明确提示。房间上下文导出与导入保留替代关系。

## 问题修复

- 修复 Agent 先通过 MCP 领取普通 `standard` 租约、Hook 随后又创建 `automatic` 租约，导致同一任务出现两张范围卡且结束后残留续租的问题。用户从界面领取的普通或独占范围继续保持人工生命周期。
- 修复 PowerShell 命令把变量、开关、枚举值、`SilentlyContinue` 或未求值的 `Join-Path` 片段误当成协作路径的问题。解析器只接受可证明的常量路径，并把仓库外目标和未跟踪临时清理保留为调用诊断。
- Agent 托管任务在 `Stop` 后进入 `awaiting_commit` 并停止续期；提交完整或改动完全撤销时由后台幂等释放，未提交或证据不完整时保留到既有 TTL。Hook 超时或短暂离线不会让已结束 Turn 继续心跳续租。
- 决定替代在单个事务中写入新决定、将旧决定标记为 `superseded`、同步记录投影并登记审计。替代必须指向同一房间的当前决定并提供非空依据；并发替代只有首个成功，后续请求返回 `409 decision_already_superseded` 和当前后继 ID。
- 已替代决定不再进入默认 Agent 上下文；旧版 `accepted` 或缺少状态的决定继续按当前决定兼容，避免升级后隐藏历史有效记录。
- Dashboard 的 500 条记录窗口会优先保留仍有效的当前决定；并发替代后的刷新若失败会明确保留陈旧状态，不再误报“当前决定已刷新”。普通决定接口一旦携带 `supersedesDecisionId`，数字、对象或空白值都会返回 `400`，不会降级为无关联的新决定。

## 兼容性与升级

- 应用版本为 `0.2.7`，协议版本保持 `2`，数据库 schema 升至 `6`，最低来源协议和 schema 保持 `1` 与 `2`。
- schema 6 增加 Agent 租约管理来源、任务级唯一约束，以及决定的 `current/superseded` 状态和单后继替代关系。v0.2.6 的 schema 5 数据会原地迁移；已运行过早期 schema 6 源码候选但缺少决定字段的数据库会幂等补齐。
- v0.2.6 及更早版本为同一决定生成不同 `decisions`/`records` ID 的历史数据，会在字段完全一致且一一对应时修复为同一 ID，使升级后的旧决定也能继续更新。房间上下文导出格式升为 v2 以保护替代关系，新版仍兼容导入 v1 备份并合并其中的分裂投影；任一区段超过 500 条时导出明确返回错误，不会生成静默截断的备份。
- 修复分裂投影 ID 时以 `decisions.status` 为真值同步 `records`，已替代的历史决定不会在重开数据库后重新变成当前决定；打包迁移探针同时覆盖真实 schema 5 数据和早期 schema 6 候选。
- REST 增加专用替代路径，MCP 决定事件增加可选 `supersedesDecisionId`；普通 `POST /api/decisions` 不提供该字段时仍按原行为新建独立决定。新客户端连接旧服务时会在写入前报告不支持，不回退成无关联记录。替代操作要求非空 `rationale`，不会按标题、路径或文本相似度自动猜测旧决定。
- 旧决定和功能修订都不会被物理删除。决定替代维护团队方案的当前视图，代码写入确认仍由功能修订影响检查负责。
- 升级期间不要卸载 Agent Hub，也不要删除 `%APPDATA%\agent-hub` 或手工修改 SQLite、连接状态和 Hook 状态文件。

## 已验证

- 两套 TypeScript 配置检查、62 个测试文件共 610 项串行测试、Vite 客户端与 Node 服务端生产构建以及完整工作树 `git diff --check` 均通过。
- 自动化覆盖 schema 2/3/4/5 与早期 schema 6 到最终 schema 6 的迁移、旧决定/记录分裂 ID 修复和幂等重开；覆盖跨成员 A→B→C 替代、缺少依据、跨房间、重复与并发替代、当前上下文过滤、v1/v2 历史链导出导入、超限导出拒绝，以及缺失目标、分叉和环形导入拒绝。
- 生产构建已在应用内浏览器完成 1264x710 桌面视口与 390x844 窄屏视口验收：默认列表和计数只显示当前决定，完整替代链可展开，更新弹窗预填正确，空判断依据会阻止提交，窄屏内容与操作区无重叠。
- Windows 标签流水线会在创建 Draft Release 前再次串行执行全量测试、NSIS 打包、更新恢复探针和打包数据库迁移探针，并生成签名更新清单与六项校验资产；任一门禁失败都不会正式发布。
